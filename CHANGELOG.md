# Changelog

Все заметные изменения проекта. Формат основан на [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## [1.11.0] — 2026-10-14

### Этап D — run-record v2 и воспроизводимость прогонов
- Сгенерированный `train_llm.py` теперь пишет `run-record.json` (schema 2) рядом с артефактами при **любом** исходе, включая честный отказ: статус и текст ошибки, время и длительность, движок/путь/рецепт, плоский конфиг, версии фактически установленных библиотек, GPU, **SHA-256 датасета** (файл или дерево каталога), метрики (train/eval loss из log_history обоих движков) и **контрольные суммы каждого артефакта**.
- Приложение: модуль `run_record.py` валидирует запись, проверяет контрольные суммы артефактов и импортирует прогон в историю (кнопка «Импорт run-record v2»); у `RunStore` появился публичный `add()`. CSV/MLflow-экспорт истории (этап 41) подхватывает поля импорта (git нет в скриптовом прогоне — окружение несёт dataset sha и версии библиотек).
- Грабли генерации: экранирование `\n` внутри генерируемого кода дважды ловилось компиляцией всех путей в тестах.

## [1.10.0] — 2026-10-14

### Этап C — производительность Trainer-пути (всё по умолчанию выключено)
- **Packing с доказуемой изоляцией:** примеры упаковываются до seq_len; изоляция держится на position_ids с нуля у каждого примера и маске первого токена (-100), а не на EOS. Активация только при FlashAttention-2 (CUDA + fp16/bf16 + flash-attn): без него скрипт печатает честный отказ и учит без упаковки (проверено реальным CPU-прогоном).
- **Выбор backend внимания:** flash_attention_2 при поддержке, иначе sdpa; выбор пишется в лог запуска.
- **Group by length:** колонка `length` в токенизации + `group_by_length` в TrainingArguments; галочки Packing/Group by length в мастере.
- Ускорение на GPU не измерялось (в песочнице нет GPU) и не заявляется; методология замеров — `docs/BENCHMARK.md`.

## [1.9.0] — 2026-10-14

### Этап B — TRL как альтернативный движок LoRA
- В мастере появился выбор движка: Авто / Trainer (HF) / TRL SFTTrainer. `Авто` выбирает TRL для чат-рецепта при установленном `trl`, иначе Trainer. Старый путь не изменён в поведении и остаётся fallback.
- Сгенерированный скрипт получил `train_lora_trl` (TRL SFTTrainer 0.12). Честные ограничения, задекларированные в коде и логе: TRL 0.12 не маскирует completion сам — датасет подаётся предтокенизированным нашим проверенным маскированием с явным коллатором; packing в TRL-пути не применяется (этап C); resume в TRL-пути честно отказывает в пользу Trainer-пути; при отсутствии chat template у токенизатора применяется минимальный шаблон с предупреждением в логе.
- Общий SFT-конвейер (пары/токенизация/маски) вынесен в helpers генерируемого скрипта — оба движка используют один код подготовки данных.
- Найден и исправлен скрытый баг мастера: в `ScriptConfig.recipe_name` попадало отображаемое имя рецепта вместо id — UI-рецепт классификатора не мог сработать (API-тесты использовали id напрямую и бага не видели).
- Паритет после рефактора перепроверен стендом этапа A: наш путь 6.2645 против TRL 6.2671 (masked val_loss), целевые токены идентичны. TRL добавлен в CI job real-training (пин 0.12.2 под стек torch 2.5/transformers 4.46).

## [1.8.7] — 2026-10-14

### Глубокое исправление (поверх 1.8.6; пункты 1, 2, 5, 11 прошлого аудита перепроверены — закрыты в 1.8.6)
- **Chat template в LoRA:** примеры `messages` токенизируются через `tokenizer.apply_chat_template` конкретной модели, когда шаблон есть (prompt = диалог до финального assistant + generation prompt); без шаблона — прежний текстовый путь. Подтверждено реальным обучением на локальной модели с заданным шаблоном.
- **Рецепт classifier реализован по-настоящему:** `AutoModelForSequenceClassification` по полю `label`, accuracy на отложенной части, сохранение классификатора. Раньше рецепт молча запускал causal LM. Подтверждено реальным прогоном (num классов в конфиге, архитектура SequenceClassification).
- **Честность пресетов:** пресеты переименованы в «Масштаб … (своя char-модель)» с прямым указанием, что это НЕ GPT-2/Llama (нет их токенизаторов/RoPE/SwiGLU/RMSNorm); сгенерированный скрипт печатает ФАКТИЧЕСКОЕ число параметров построенной модели, а не оценку по чужому BPE-словарю.
- **Оптимизатор/планировщик:** scratch получил warmup + cosine decay (LambdaLR) вместо константного lr; LoRA — `lr_scheduler_type="cosine"` и проброс `gradient_checkpointing` из мастера в скрипт (раньше настройка терялась).
- **Resume scratch:** бандл хранит и восстанавливает оптимизатор, шаг и RNG-состояние (эпоха начинается сначала — честно сообщается; точного mid-epoch resume нет).
- **Облако:** счётчик сбоев API у задания (после 3 подряд статус честно «неизвестен», а не failed/done); бюджетный демон после 3 недоступных циклов RunPod API показывает «автостоп временно НЕ работает» вместо вечного молчания.
- **Экспорт:** успех засчитывается только артефакту ЭТОГО запуска (старые файлы в папке отсекаются по времени); ONNX проверяется структурно (protobuf ModelProto/onnx.checker, не расширение), GGUF — заголовок (версия и счётчики).
- **Оценка качества:** новый `quality_eval` — фиксированные задания до/после обучения (responder инъектируется), скан метрик на NaN/Inf/расходимость, честный сравнительный вердикт. Loss сам по себе качеством не считается.

## [1.8.6] — 2026-10-14

### Верификация четвёртого аудита (остаточные проблемы 1.8.5)
- **RunPod: поле команды исправлено на `args`** — сверено с официальным runpod-python (`ctl_commands.create_pod`: `body["args"] = docker_args`, REST v2); поля `dockerArgs` в v2 нет. Тест, закреплявший неверный формат, переписан.
- **LoRA маскирование prompt по-настоящему:** раньше changelog 1.8.2 заявлял маскировку, а по факту labels копировали все токены. Добавлены `_row_pair`/`_mask_labels` в генерируемый скрипт: loss только по целевому ответу для instruction/messages/prompt-completion (проверено исполнением сгенерированного кода).
- **BF16 по факту поддержки GPU:** `is_bf16_supported()` → иначе FP16; то же для QLoRA compute dtype (Tesla T4 и др.).
- **Scratch-методология:** grad_accum больше не повторяет один микробатч (сид включает номер микробатча); валидация — 4 РАЗНЫХ батча, а не один; в лог пишется средний loss по микробатчам; в DDP метрики/сэмплы печатает только главный процесс.
- **Scratch resume:** из бандла восстанавливаются также `arch` и `seq` (не только словарь) — проверено реальным resume со сменённым пресетом.
- **Бюджет:** повреждение журнала и сбой его сохранения больше не подавляются: `BudgetVerdict.warning` (виден в интерфейсе и у демона), сбой записи при submit пишется в лог задания.
- **Потоковость:** LoRA строит датасет через `Dataset.from_generator` (Arrow на диске) с потоковым чтением файла; аудит хранит 16-байтные хэши вместо полных текстов в `seen`.
- **Настройки:** поля с `default_factory` (`hotkeys`, `plugin_market_urls`) теперь реально валидируются (был `MISSING`-пропуск).
- **Очередь:** повреждённый `cloud_jobs.json` — копия `.corrupt-*` + `load_error`, не-словарные записи не роняют загрузку.
- **SemVer:** полный порядок prerelease по §11 (цепочка alpha → alpha.1 → alpha.beta → beta → beta.2 → beta.11 → rc.1 → release в тестах).
- **`--require-torch` теперь гарантирует и LoRA-прогон**; тест DDP усилен: оба ранга стартовали, метрики не дублируются, «Готово» печатает только главный процесс.

## [1.8.5] — 2026-10-14

### Верификация третьего аудита (остаточные проблемы 1.8.4)
- **LoRA:** добавлен `DataCollatorForSeq2Seq` (динамический padding, labels паддятся -100) — батчи разной длины больше не падают; `trainer.evaluate()` вызывается только при наличии val-выборки. Подтверждено НАСТОЯЩИМ обучением: крошечная GPT-2 + токенизатор собраны локально (без HF Hub), сгенерированный скрипт обучил адаптер (val_loss получен, adapter_model сохранён).
- **Scratch, малые датасеты:** честный fail-fast до обучения («нужно >= 4*seq+8 токенов») вместо падения randint/совпадения train==val.
- **Scratch, resume:** словарь `stoi/itos` восстанавливается из бандла чекпоинта до построения модели — resume с изменившимся корпусом загружает веса корректно (подтверждено реальным прогоном).
- **Scratch, DDP:** устройство по `LOCAL_RANK` (+`set_device`), отдельный сид сэмплера на ранг и шаг (ранги больше не едят одни батчи), сохранение чекпоинтов только на главном процессе. Подтверждено реальным `torchrun --nproc_per_node=2` на CPU (gloo): у рангов разные loss, чекпоинт один.
- **Облако/бюджет:** поды из очереди заданий и агента помечаются `managed=True` в журнале бюджета при submit (страж вправе их автостопить); повреждённый `budget.json` сохраняется копией `budget.json.corrupt-*` с `load_error`, а не обнуляется молча.
- **Отмена задания:** если pod завершить не удалось, задание НЕ помечается cancelled (ошибка пользователю: расходы могут продолжаться); без клиента — локальная отмена с честным предупреждением в логе.
- **EXITED != успех:** pod в статусе EXITED переводит задание в done только с пометкой «успешность обучения НЕ подтверждена — проверьте логи/метрики».
- **RunPod create_pod:** после создания статус пода подтверждается запросом списка; сразу упавший под — ошибка; в результат добавлен честный `command_status` (API не подтверждает выполнение dockerArgs).
- **`real_check --require-torch`:** флага фактически не было (утрачен при переписывании скрипта) — реализован: без torch проверка завершается кодом 1 (проверено поведенчески, со скрытым torch). В real_check и CI добавлено настоящее LoRA-обучение.
- **Сравнение:** скорость сходимости считается по той же метрике, что и сравнение качества (val_loss первична), а не по train loss.

## [1.8.2] — 2026-10-14

### Верификация внешнего аудита (28 пунктов) — подтверждено и исправлено
- **LoRA не могла учиться**: tokenization не строила `labels` для маскированного LM — добавлены (`-100` на prompt-части при `instruction`).
- **Scratch: ложный val_loss** (печатался train loss): настоящая отложенная выборка (последние 10% токенов) и периодический eval.
- **Загрузка датасетов в скриптах падала на битой JSON-строке** и не понимала формат `messages` — потоковый разбор с пропуском плохих строк.

- **Сравнение прогонов смешивало метрики** (train вместо val, best из разных шкал) — одна сопоставимая метрика на прогон; разные метрики у A/B → «Несопоставимо».
- **Переобучение определялось одной точкой** — ужесточена эвристика (+20% скачок или монотонный рост ≥2 точек) и все вердикты честно помечены «эвристика».
- **Dataset preview молча обрезался на 200 000 символах** — потоковое чтение.
- **`run_command` возвращал ok=True при любом коде выхода** — теперь `ok = (returncode == 0)`.
- Таск-лог обучения целиком читался в память (tail через seek), имена логов сталкивались в пределах секунды (микросекунды+pid), stop() не добивал дочерние процессы (process group на POSIX).
- **Облачная очередь**: запись была неатомарной (tmp+replace), cancel не трогал реальный под (terminate через клиент), один пропуск в API сразу хоронил задание (failed после 2 пропусков), добавлена честная оговорка про dockerArgs.
- **Бюджет**: расходы пода терялись при рестарте/пересоздании (сегментная модель `closed_usd`), stopped по первому пропуску API (грейс 2), автостоп мог остановить ЧУЖИЕ поды аккаунта (только `managed` — созданные приложением); плюс `sync_ledger` теперь понимает `desiredStatus` RunPod.
- Тест `status().running or True` (проверка-ничто) заменён настоящим тестом живого процесса; ветка текущей разработки добавлена в windows-build; в CI отдельный job `real-training` с настоящим torch и `real_check.py --require-torch`.

### Не подтвердилось (по коду)
- «create_pod не передаёт команду» — передаёт (`dockerArgs`); реальный риск — entrypoint образа, теперь честно пишется в лог задания.
- «Песочница плагинов небезопасна» — ограничение прямо раскрыто в docstring («not a hard OS-level jail»); подаётся как изоляция API, а не тюрьма ОС.

## [1.8.0] — 2026-10-14

### Добавлено
- **Этап 48 — фоновый бюджетный демон**: общий потолок расходов теперь охраняется всегда, а не только при открытии страницы GPU. Каждые 2 минуты демон (по таймеру главного цикла, сеть — в executor) сверяет поды аккаунта с журналом `budget.json` и при превышении потолка останавливает поды, пишет событие в ленту активности и статус «⛔ Бюджет».
