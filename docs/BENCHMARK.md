# Этап A — методология и результаты сравнения движков

## Методология (воспроизводимо)
Команда: `.venv/bin/python scripts/bench_engines.py --work /tmp/alterego-bench-a`
(скрипт: `scripts/bench_engines.py`, seed=42 везде).

Одинаково для обоих движков:
- исходные веса: одна локально собранная GPT-2 (2 слоя, d=32) — каталог `base`;
- токенизатор: один WordLevel, один chat template для обоих;
- датасет: 512 синтетических `messages` (user/assistant), файл `data.jsonl`;
- маски: loss только по assistant (наш `_mask_labels` / TRL completion-only);
- сплит: `train_test_split(test_size=51, seed=42)` — один и тот же набор;
- LoRA: r=16, alpha=32, dropout 0.05, target `c_attn`, batch 4, seq 64, 1 эпоха, lr 1e-4 cosine;
- оценка: маскированный val_loss на отложенных 51 примере общим оценщиком
  (`eval_adapter.py` в рабочем каталоге стенда), целевых токенов: 426 у обоих.

Качество на синтетике НЕ обобщается: это измерение сопоставимости и цены,
а не «ума». Отдельная качественная оценка — `quality_eval` на фиксированных
заданиях (этап по плану, не этот стенд).

## Этап C — производительность (добавлено в 1.10.0)
Реализовано в Trainer-пути, всё по умолчанию ВЫКЛЮЧЕНО:
- `packing` — упаковка примеров до seq_len. Изоляция: position_ids с нуля
  у каждого примера + первый токен примера замаскирован (-100); EOS
  защитой не считается. Активируется ТОЛЬКО при FlashAttention-2
  (CUDA + fp16/bf16 + пакет flash-attn), иначе скрипт честно печатает
  отказ и учит без упаковки. На CPU-стенде ускорение не измерялось и
  не заявляется; корректность границ проверена юнит-тестом упаковки.
- backend внимания: flash_attention_2 при поддержке, иначе sdpa, на CPU —
  умолчание transformers; выбор печатается в лог запуска.
- `group_by_length` — батчи из похожих по длине (колонка length в
  токенизации); включён в реальный CPU-прогон тестов — обучение завершается.
Замеры ускорения на GPU — за пользователем с железом; стенд этапа A
расширяется теми же командами (`packing=True` в ScriptConfig).
