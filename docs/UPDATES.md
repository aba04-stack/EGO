# Подписанные обновления (этап G)

## Формат манифеста (schema 1)
`{version, url, sha256, size, signature}` — подпись Ed25519 по каноничному
JSON манифеста без поля `signature` (ключи отсортированы, без пробелов).

## Сторона релизера
```bash
python scripts/sign_update.py make-keys --out-dir keys/   # один раз; private.pem — секрет CI, не коммитить
python scripts/sign_update.py sign --artifact app.zip --version 1.14.0 \
    --url https://example.com/app.zip --key keys/private.pem --out manifest.json
```
`public.pem` встраивается распространителем в конфигурацию приложения.

## Сторона приложения (`signed_update.apply_update`)
1. Манифест без schema/полей или с битой подписью отклоняется.
2. Версия не новее текущей отклоняется (anti-rollback; обход —
   `allow_downgrade=True` явным решением).
3. SHA-256 и размер скачанного артефакта сверяются; несовпадение — отказ,
   текущий файл не тронут.
4. Замена атомарна: запись во временный файл в том же каталоге, fsync,
   `os.replace`; предыдущая версия остаётся в `.bak`, откат — `rollback()`.
Без пакета `cryptography` подпись проверить нечем — обновление честно
недоступно, «на веру» ничего не применяется.

## Чего здесь нет
Скачивание по сети и UI-диалог применения — следующий шаг поверх этой
проверенной механики; подпись установщика Windows (Authenticode) требует
сертификата издателя и в репозитории не имитируется.

## Зависимость cryptography: решение (1.15.0)
Не входит в обязательные runtime-зависимости приложения (без неё приложение
работает, обновления честно отключены), но **обязательна для релизной
сборки**: добавлена в extra `package` (PyInstaller-бандл) и в `dev`, а CI
прогоняет G-тесты отдельным шагом с `ALTEREGO_REQUIRE_CRYPTO=1` — в этом
режиме отсутствие cryptography является ошибкой сборки, а не пропуском.

## Защита закрытого ключа
- `.gitignore`: `keys/`, `*.pem`, `*.key`, `private*.pem`, `*_private.pem`.
- `sign_update.py make-keys`: каталог 0700, `private.pem` создаётся с 0600.
- `sign_update.py check <пути>` ищет закрытые ключи по именам и содержимому
  PEM в артефактах; CI выполняет проверку на собранном `dist/`.

## Атомарность (1.15.0)
Уникальный временный файл (`tempfile`, тот же каталог), fsync, сверка хэша
временного файла до замены, атомарная `.bak` (тоже сверена по хэшу),
эксклюзивный `.update.lock` (O_EXCL) против конкурирующих обновлений,
очистка временного файла при любой ошибке. При отказе до `os.replace`
установленный файл остаётся байт-в-байт прежним — проверено тестами с
инъекцией ошибок записи и замены.
